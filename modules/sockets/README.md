# Модуль Sockets

WebSocket-сервер на Socket.IO. Модуль наследуется от API, поэтому часть архитектуры (создание событий, конфигурация) аналогична.

## Файл конфигурации

| Параметр | Тип | Описание |
|---|---|---|
| `port` | `string` | Порт сервера. Поддерживает интерполяцию: `${SOCKETS_PORT}` |
| `paths.events` | `string` | Директория с обработчиками событий |

## SSL

SSL-сертификаты управляются модулем [SSL](../ssl/). Если SSL-модуль предоставляет credentials, сервер запускается по HTTPS, иначе — по HTTP.

## Создание событий

Создайте каталог с именем события внутри соответствующей ветки, добавьте `index.js` и `config.json`. Структура аналогична методам API.

### Ветки событий

| Ветка | Описание | Когда загружается |
|---|---|---|
| `events/io/` | События серверного уровня (например, `connection`) | При старте сервера |
| `events/socket/` | События для каждого подключения | При каждом новом подключении клиента |

Ветка `io` инициализируется при запуске модуля. Ветка `socket` инициализируется внутри обработчика `connection` — для каждого нового подключенного клиента создаются свои обработчики событий.

### config.json события

```json
{
    "use": true,
    "params": []
}
```

Формат параметров идентичен API-методам, за исключением поля `method`.

### index.js события

В метод `getResponse` передается экземпляр сокета (для ветки `io`, например в событии `connection`) или данные от клиента (для ветки `socket`).
